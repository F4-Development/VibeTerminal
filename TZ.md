# Vibe Vim — техническое задание

## Коротко

**Vibe Vim** (команда `vv`) — терминальный пульт для вайбкодинга. В одном окне работают несколько Claude Code. Видно, кто работает, кто ждёт тебя и кто закончил. Изменения удобно проверять и комментировать. Уведомления приходят на Mac и в Telegram. Пока агенты работают, играет тикток. Голосом управляешь и агентами, и компом (Джарвис).

- Платформа: macOS 14+ на Apple Silicon.
- Язык: Rust, один бинарник без зависимостей.
- Внутри обычный `claude`. Свой агент и свой редактор не пишем.

**Главное правило: вся работа на виду.** Claude живут только внутри открытого окна `vv`. Закрыл терминал или вышел из `vv` — все Claude остановились. Никаких невидимых фоновых процессов. Прошлые диалоги можно продолжить при следующем запуске.

---

## Как работаем

1. Я делаю один шаг из списка ниже, собираю и ставлю `vv` (`cargo install --path .`, бинарник в `~/.cargo/bin`).
2. Пишу в чат, что появилось, и чеклист для проверки (он же в этом файле).
3. Ты проверяешь и пишешь, что не так или что хочешь иначе.
4. Правлю и перехожу к следующему шагу. Каждый шаг — отдельный коммит, любой можно откатить.

Главный терминал для тестов — тот, где ты реально будешь сидеть. Сейчас это терминал PhpStorm. Обязательно поддерживаем ещё Ghostty и iTerm2.

## Шаги

### Этап A. Основа

#### Шаг 1. Claude внутри vv

**Что делает**
- `vv` в любой папке открывает на весь экран интерфейс: вверху строка с названием, внизу строка статуса, в центре живой Claude Code в этой папке.
- Claude работает в настоящем терминале (PTY). Всё, что умеет обычный `claude`, работает так же.
- Колесо мыши прокручивает историю вывода. Ввод возвращает вниз.
- Выход: `/exit` в Claude или `Ctrl-\` → `q`.

**Проверка**
- [ ] `vv` в папке проекта открывает Claude именно в этой папке
- [ ] Цвета, рамки и спиннер выглядят как в обычном терминале
- [ ] Печать без задержек; работают стрелки, Tab, Shift+Tab, Esc (прервать), Ctrl+R
- [ ] Вставка большого многострочного текста приходит одним куском
- [ ] Русский текст печатается и отображается правильно
- [ ] Колесо мыши листает историю
- [ ] Текст выделяется мышью с зажатым Option или Shift (зависит от терминала) и копируется
- [ ] При изменении размера окна Claude перерисовывается без мусора
- [ ] `/exit` и `Ctrl-\` `q` закрывают vv

#### Шаг 2. Несколько сессий

**Что делает**
- Слева список сессий, справа экран выбранной.
- `Ctrl-\` переводит в режим NORMAL (управление vv), `Enter` или `i` возвращает в Claude.
- `n` — новая сессия. Выбор папки с поиском по мере ввода: сначала недавние (где уже запускал Claude), потом всё из `~/Projects`. Можно вписать путь.
- `j`/`k` или стрелки — выбрать сессию, её экран сразу видно справа. `1`–`9` — сессия по номеру. Клик мышью по сессии в списке открывает её.
- `R` — переименовать, `X` — закрыть (с подтверждением), `z` — спрятать или показать список, `?` — подсказка по клавишам.
- Имя сессии по умолчанию — имя папки. Для двух сессий в одной папке — `shop-api`, `shop-api-2`. Под именем — тема диалога, которую Claude пишет в заголовок.
- `q` — выйти из vv. Спрашивает подтверждение: все Claude остановятся.
- **Честное закрытие.** Закрыл вкладку или окно терминала, или vv упал — все Claude внутри останавливаются сразу.
- Если Claude закрылся сам (`/exit`), сессия пропадает из списка. Закрылась последняя — vv выходит.

**Проверка**
- [ ] Открыл 3 сессии в разных папках и переключаюсь между ними
- [ ] Пока бегаю по списку, справа видно живой экран каждой сессии
- [ ] Две сессии могут работать одновременно
- [ ] Поиск папки находит проект по куску названия, в том числе в русской раскладке
- [ ] Переименование и закрытие работают, закрытие спрашивает подтверждение
- [ ] Дал задачу, закрыл вкладку терминала — этого Claude больше нет в «Мониторинге системы» (или в `pgrep -fl claude`)

#### Шаг 3. Продолжить после закрытия

**Что делает**
- vv помнит открытые сессии (`~/.vibevim/state.json`): имя, папку, ID диалога Claude.
- Следующий `vv` показывает прошлые сессии в списке со значком `×`. Сами они не запускаются — ничего не работает без твоего ведома.
- `Enter` на такой сессии — Claude продолжает тот же диалог (`claude --resume`). `X` — убрать из списка.
- `vv` в папке, где уже была сессия, сразу выбирает её.

**Проверка**
- [ ] Открыл 2 сессии, поговорил, вышел из vv — при следующем `vv` обе в списке со значком `×`
- [ ] `Enter` на `×` — тот же диалог, с историей
- [ ] Пока не нажал `Enter`, Claude не запущен

#### Шаг 4. Статусы

**Что делает**
- У каждой сессии в списке значок, время в текущем статусе и вторая строка с деталями (см. «Статусы»).
- `gn` — перейти к следующей сессии, которая ждёт тебя.
- В строке статуса: «ждут тебя: 2».

**Проверка**
- [ ] Дал задачу — `●`, во второй строке меняются действия (`Edit src/…`, `$ npm test`)
- [ ] Claude просит разрешение на команду — `!` и текст запроса
- [ ] Claude задал вопрос с вариантами — `!`
- [ ] Закончил — `✓` и первая строка его ответа; открыл сессию — стало `○`
- [ ] Прервал по Esc — `○`, а не вечное `●`
- [ ] `gn` ведёт к `!`, потом к `✓`

#### Шаг 5. Разрешения прямо в vv

**Что делает**
- Когда Claude просит разрешение, внизу его экрана появляется панель vv:

  ```
  ┌ landing просит разрешение ──────────────────────────────┐
  │ Bash: npm i zod                                         │
  │ [a] разрешить   [x] отклонить   [Enter] диалог Claude   │
  └─────────────────────────────────────────────────────────┘
  ```
- `a`/`x` работают и из списка сессий: разрешил, не заходя в сессию.
- `Enter` показывает обычный диалог Claude со всеми вариантами («больше не спрашивать» и т.п.).
- Это основа для кнопок в Telegram и ответов голосом.

**Проверка**
- [ ] `a` разрешает, Claude продолжает
- [ ] `x` отклоняет, Claude видит отказ
- [ ] Из списка сессий можно разрешить, не заходя в сессию
- [ ] `Enter` показывает родной диалог Claude

#### Шаг 6. Уведомления на Mac

**Что делает**
- Баннер со звуком, когда сессия:
  - ждёт тебя;
  - закончила (если работала дольше 30 с — настраивается);
  - упала.
- Не беспокоит, если ты прямо сейчас смотришь на эту сессию и терминал активен.
- Клик по уведомлению выводит терминал вперёд и открывает нужную сессию.
- Новое уведомление той же сессии заменяет старое, а не копится.
- Нужен `terminal-notifier` (поставлю через brew). Если будет глючить — свой мини-helper.

**Проверка**
- [ ] Дал задачу, ушёл в браузер — пришло уведомление, когда закончил
- [ ] Клик открыл терминал на нужной сессии
- [ ] Смотрю на сессию — уведомлений нет
- [ ] Звук есть, его можно поменять в настройках

#### Шаг 7. Настройки (Lua)

**Что делает**
- Конфиг: `~/.config/vibevim/init.lua`. `vv config` открывает его в редакторе.
- `:reload` применяет изменения без перезапуска сессий.
- Ошибка в конфиге показывается в строке статуса, а vv не падает и работает на прошлых настройках.
- На этом шаге настраиваются:
  - клавиши и цвета;
  - ширина и сторона списка сессий;
  - звуки и пороги уведомлений;
  - папки с проектами;
  - команда и флаги `claude`;
  - свои команды `:xxx`;
  - обработчики событий `vv.on(...)`.
- Настройки только для одного проекта: файл `.vibevim.lua` в корне проекта. При первом запуске vv спрашивает, доверять ли ему (как `direnv allow`).

**Проверка**
- [ ] Поменял клавишу `Ctrl-\` на другую — работает после `:reload`
- [ ] Добавил свою команду `:ship`, которая отправляет Claude текст
- [ ] Повесил на «закончил» свою реакцию (например, `say готово`)
- [ ] Сломал конфиг — vv не упал и показал ошибку

#### Шаг 8. Отдельная копия проекта на задачу (worktree)

**Что делает**
- `N` — новая сессия в отдельной копии проекта (`git worktree`) на новой ветке. Параллельные агенты не мешают друг другу.
- Копии лежат в `~/.vibevim/worktrees/<проект>/<ветка>`, в списке сессий видна ветка.
- В копию переносятся `.env*` (список настраивается) и выполняется команда подготовки из настроек проекта (например, `npm i`).
- При закрытии такой сессии выбор: оставить копию или удалить её. Ветка при удалении остаётся.

**Проверка**
- [ ] `N` → ввёл `feat-login` → Claude работает в копии на ветке `feat-login`
- [ ] Основная папка проекта не тронута
- [ ] `.env` скопировался, `npm i` отработал
- [ ] При закрытии предложило удалить копию

### Этап B. Проверка изменений

#### Шаг 9. Экран изменений

**Что делает**
- `r` открывает экран изменений выбранной сессии: слева файлы, справа diff с подсветкой синтаксиса.

  ```
   REVIEW  shop-api · последняя задача · 3 файла +130 −3        ? — клавиши
  ──────────────────────────────────────────────────────────────────────────
   M src/auth.ts   │  13 −   const user = db.find(req.body.email)
   A src/jwt.ts    │  13 +   const user = await db.users.findOne(...)
   M package.json  │  14 +   if (!user) throw new Error("not found")
  ```
- Два режима, переключаются по `m`:
  - **последняя задача** (по умолчанию): что Claude поменял с момента твоего последнего сообщения. vv запоминает состояние файлов в момент отправки;
  - **всё незакоммиченное**.
- Навигация:
  - `j`/`k` — по строкам;
  - `]c`/`[c` — к следующему или предыдущему изменению;
  - `Tab` — к следующему файлу.
- `u` откатывает кусок изменений под курсором (с подтверждением).
- `e` открывает файл на этой строке в твоём редакторе (`$EDITOR`, PhpStorm, Cursor и т.п. — настраивается).
- `q` — назад.

**Проверка**
- [ ] После задачи `r` показывает ровно то, что Claude поменял в этой задаче
- [ ] `m` переключает на всё незакоммиченное
- [ ] Подсветка синтаксиса есть, новые файлы тоже видно
- [ ] `u` откатил кусок, файл реально вернулся
- [ ] `e` открыл файл на нужной строке

#### Шаг 10. Комментарии → Claude

**Что делает**
- `c` пишет комментарий к строке, `v` выделяет несколько строк, потом `c`. Комментарий виден под строкой.
- `dd` на комментарии удаляет его.
- `S` отправляет все комментарии Claude одним сообщением:
  ```
  Правки по ревью:
  1. src/auth.ts:14 `if (!user) throw new Error("not found")`
     → тут верни 401, а не кидай исключение
  2. src/jwt.ts:3-8
     → вынеси секрет в env
  ```
- Комментарии не теряются, если выйти из ревью или закрыть vv.

**Проверка**
- [ ] Оставил 2–3 коммента, `S` — Claude получил их одним сообщением и начал править
- [ ] Вышел из ревью, вернулся — неотправленные комменты на месте

### Этап C. Telegram

#### Шаг 11. Бот: уведомления

  - `✅ shop-api · 4 мин 12 с` + итог;

#### Шаг 12. Кнопки и ответы

**Что делает**
- На запрос разрешения кнопки **[Разрешить] [Отклонить]**. После нажатия сообщение меняется на «✅ разрешено».
- Если ответить (reply) на сообщение бота, текст уходит этой сессии как новая задача.

  - `/stop <сессия>` — прервать;
  - `/diff <сессия>` — сводка изменений + файл с diff.
- Решение, принятое в Telegram, сразу видно в vv, и наоборот.

### Этап E. Голос и Джарвис

#### Шаг 16. Слышит своё имя

**Что делает**
- `vv voice setup` скачивает модели распознавания (≈0,7 ГБ) и запрашивает доступ к микрофону.
- vv слушает всегда, но реагирует только на фразы, которые начинаются с имени. По умолчанию имя «Джарвис», меняется в настройках, можно задать несколько.
- «Джарвис, <команда>» — одной фразой. Или «Джарвис», короткий звук, потом команда.
- В строке статуса: `🎙` и распознанный текст. На этом шаге только показываем текст, ничего не выполняем.
- `m` (или «Джарвис, не слушай») выключает микрофон, `m` включает обратно.
- Всё распознаётся на компе. Аудио не сохраняется и никуда не уходит.

**Проверка**
- [ ] «Джарвис, привет» — звук и текст в строке статуса
- [ ] Русский вперемешку с английскими словами («сделай refactor этого хука») распознаётся нормально
- [ ] 10 минут обычного разговора рядом — ложных срабатываний нет
- [ ] Поменял имя в настройках — реагирует на новое

**Проверка**
- [ ] Когда сессия ждёт, это сказали вслух
- [ ] Голос и громкость устраивают, можно выключить

#### Шаг 21. Джарвис: проекты и агенты

**Что делает**

## Как устроено

### Процессы

```
 ┌───────────────────────────── vv (окно терминала) ─────────────────────────────┐
 │ интерфейс · сессии (PTY + эмулятор экрана) · статусы · Lua · Telegram · голос │
 └──────┬──────────────────────▲───────────────────────▲──────────────────┬──────┘
        │ PTY                  │ сокет                 │ сокет            │
  claude × N (+ Джарвис)   vv hook (зовёт Claude)   vv mcp (Джарвис)   vv media (окно тиктока)
```

- Всё живёт в одном процессе `vv`. Закрыл окно — остановилось всё: Claude, окно тиктока, голос, Telegram-бот.
- `vv hook` и `vv mcp` — короткоживущие помощники. Они общаются с окном vv через его сокет.
- Можно открыть vv в двух окнах: это две независимые копии. Telegram и голос работают в одной из них — в первой открытой.

### Команды

| Команда | Что делает |
|---|---|
| `vv [папка]` | Открыть vv, сессия в текущей (или указанной) папке |
| `vv config` | Открыть конфиг |
| `vv doctor` | Проверить зависимости и доступы (микрофон, уведомления, Accessibility) |
| `vv telegram setup` / `vv voice setup` | Настройка |
| `vv hook`, `vv mcp`, `vv media` | Служебные, руками не вызываются |

### Связь с Claude Code

- Каждая сессия запускается так: `claude --session-id <uuid> --settings ~/.vibevim/run/hooks.json [флаги из конфига]`, с переменными окружения `VV_SESSION=<id>` и `VV_SOCK=<сокет этого окна vv>`.
- Хуки подключены только к нашим сессиям через `--settings`. Твой `~/.claude/settings.json` не трогаем, обычный `claude` вне vv работает как раньше.
- Все хуки вызывают `vv hook`. Он читает JSON от Claude и пересылает окну vv, которое запустило эту сессию. На запрос разрешения (`PermissionRequest`) ждёт решения и возвращает его Claude. Пока хук ждёт, Claude свой диалог не показывает. Если хук ответил пустым или вышло время ожидания (задаём с запасом), появляется обычный диалог Claude.
- Какие хуки используем:
  - `UserPromptSubmit` — работает;
  - `PreToolUse` / `PostToolUse` — текущее действие; на `AskUserQuestion` и `ExitPlanMode` — ждёт;
  - `PermissionRequest` и `Notification` (`permission_prompt`) — ждёт;
  - `Stop` — готово (итог берём из `transcript_path`);
  - `SessionEnd` — завершена.
- **Хук никогда не ломает Claude**: если окно vv недоступно, `vv hook` за миллисекунды молча выходит с кодом 0.
- `--session-id` задаём сами, поэтому знаем ID диалога и можем продолжить его через `--resume` после перезапуска.

### Главный экран

```
 vibe vim                                      🎙 джарвис · ▶ tiktok · 14:32
─────────────────────┬────────────────────────────────────────────────────────
 ◆ джарвис           │ shop-api · feat/auth
 ● shop-api   3m12s  │

 ○ scratch           │
─────────────────────┴────────────────────────────────────────────────────────
 AGENT │ shop-api │ ждут тебя: 2 (gn)
```

### Режимы

| Режим | Что делаешь | Как попасть |
|---|---|---|
| AGENT | Все клавиши идут в Claude | `Enter` / `i` из NORMAL |
| NORMAL | Управляешь vv | `Ctrl-\` из AGENT |
| COMMAND | Команды `:xxx` | `:` из NORMAL |
| REVIEW | Смотришь и комментируешь изменения | `r` из NORMAL |

### Клавиши (по умолчанию, все меняются)

| Клавиша | Где | Действие |
|---|---|---|
| `Ctrl-\` | AGENT | В NORMAL |
| `Ctrl-\` `Ctrl-\` | AGENT | Отправить сам `Ctrl-\` в Claude |
| `Enter` / `i` | NORMAL | В Claude выбранной сессии |
| `j` `k` / стрелки | NORMAL | Выбрать сессию |
| `1`–`9` | NORMAL | Сессия по номеру |
| `gn` | NORMAL | Следующая, кто ждёт тебя |
| `n` / `N` | NORMAL | Новая сессия / новая в отдельной копии |
| `R` / `X` | NORMAL | Переименовать / закрыть |
| `a` / `x` | NORMAL, панель разрешения | Разрешить / отклонить |
| `r` | NORMAL | Ревью |
| `t` | NORMAL | Тикток |
| `m` | NORMAL | Микрофон вкл/выкл |
| `z` | NORMAL | Спрятать список сессий |
| `Ctrl-u` / `Ctrl-d`, колесо | NORMAL | Прокрутка истории |
| `q` | NORMAL | Выйти из vv (с подтверждением: все Claude остановятся) |
| `?` | везде кроме AGENT | Подсказка |

Команды: `:new`, `:rename`, `:kill`, `:review`, `:reload`, `:config`, `:voice on|off`, `:media on|off`, `:q`.

**Русская раскладка.** В NORMAL и REVIEW буквы работают в любой раскладке (`о` = `j`, `л` = `k`, как `langmap` в vim). Для сочетаний с Ctrl используем kitty keyboard protocol там, где терминал его знает. Отдельно проверяем в терминале PhpStorm.

**Цвета.** По умолчанию берутся из палитры твоего терминала, поэтому vv выглядит родным. Меняются в конфиге.

## Статусы

| Статус | Значок | Когда | Вторая строка |
|---|---|---|---|
| пусто | `○` | Запуск; ты открыл «готово»; прервал по Esc | — |
| работает | `●` | Отправил сообщение; разрешил; ответил на вопрос | Текущее действие |
| ждёт | `!` | Запрос разрешения; вопрос с вариантами; план на утверждение | Что просит |
| готово | `✓` | Claude закончил ответ | Первая строка ответа |
| завершена | `×` | Процесс `claude` закрылся | Код выхода |

Правила:
- `!` → `●`:
  - решение через vv, Telegram или голос;
  - любой ввод в терминал этой сессии;
  - событие о завершении инструмента.
- `✓` → `○` — ты открыл сессию. `✓` работает как «непрочитанное».
- `●` → `○` по Esc. У Claude Code нет хука на прерывание, поэтому vv сам ловит нажатие Esc в этой сессии. Если после него нет новых событий, статус становится «пусто».
- Очередь «ждут тебя»: сначала все `!` (кто дольше ждёт — первым), потом `✓`.
- Как выглядит текущее действие:
  - Bash → `$ команда`;
  - Read/Edit/Write → путь от корня проекта;
  - Grep/Glob → шаблон;
  - WebFetch/WebSearch → домен или запрос;
  - Task → описание подзадачи;
  - MCP → `сервер:инструмент`.

## Тикток: когда играет

Работает, только когда тикток-режим включён (`t`).

| Событие | Что делает |
|---|---|
| Хоть одна сессия работает > 20 с, никто не ждёт | ▶ Play |
| Сессия ждёт тебя | ⏸ Сразу; размытие с надписью «landing ждёт тебя»; терминал вперёд |
| Сессия закончила | ⏸ После текущего ролика (но не дольше 60 с) |
| Ты отправил сообщение | ▶ Через 20 с работы, чтобы не дёргалось на коротких задачах |
| Ты сказал «Джарвис» | Звук тише, пока говоришь |
| Ты сам нажал паузу | Автоплей молчит до следующей задачи |

Всё настраивается: задержки, «пауза сразу» или «после ролика», выводить ли терминал вперёд.

## Настройки (Lua)

```lua
-- ~/.config/vibevim/init.lua
vv.setup {
  prefix   = "<C-\\>",
  claude   = { cmd = "claude", args = {} },
  projects = { "~/Projects" },
  sidebar  = { width = 24, side = "left" },
  editor   = "phpstorm --line {line} {file}",
  notify   = { sound = "Glass", done_min_seconds = 30, away_after_min = 3 },
  worktree = { copy = { ".env", ".env.local" } },
  media    = { source = "tiktok", resume_after = 20, on_done = "after_video" },
  voice    = { names = { "джарвис", "jarvis" }, tts = "say:Milena" },
  jarvis   = { model = "sonnet" },
}

vv.command("ship", function(s)
  s:send("прогони тесты, если зелёные — закоммить и запушь")
end)

vv.on("done", function(s)
  if s.duration > 600 then vv.say(s.name .. " наконец-то закончил") end
end)

vv.voice.command("кофе", function() vv.shell("open -a 'Coffee Timer'") end)
```

- Lua выполняется внутри vv и работает, пока окно открыто.
- События: `session_new`, `status`, `working`, `waiting`, `done`, `exited`, `review_sent`, `away`, `back`, `voice_heard`, `media`.
- API:
  - `vv.sessions.list/get/current/new`;
  - `s:send`, `s:interrupt`, `s:focus`;
  - `vv.map`, `vv.command`, `vv.notify`, `vv.telegram.send`, `vv.say`;
  - `vv.media.*`, `vv.user.away()`, `vv.shell`.
- Встроенные фичи (тикток, эскалация уведомлений) сделаны теми же Lua-плагинами. Их можно открыть и переписать.

## Нефункциональные требования

- **Лёгкость.**
  - Бинарник < 30 МБ.
  - vv без голоса < 50 МБ RAM (плюс история вывода, по умолчанию 10k строк на сессию).
  - В простое CPU ≈ 0%: никакого опроса по таймеру, всё по событиям.
  - С голосом: +≈1 ГБ RAM и < 5% одного ядра на постоянное прослушивание.
- **Скорость.**
  - Интерфейс `vv` открывается < 300 мс (плюс запуск самого Claude).
  - Задержку ввода в Claude на глаз не заметно.
  - Перерисовка только при изменениях, не чаще 60 раз в секунду.
- **Надёжность.**
  - Падение окна тиктока или голоса не трогает сессии.
  - Если упал сам vv, Claude останавливаются вместе с ним — работа не идёт невидимо. Диалоги можно продолжить при следующем запуске.
  - Хук не ломает Claude.
  - Ошибка в конфиге не роняет vv.
- **Безопасность.**
  - Сокет доступен только тебе.
  - Telegram — только твой chat_id.
  - Ключи — в Связке ключей.
  - Настройки проекта исполняются только после подтверждения доверия.
  - Опасные действия — только с подтверждением клавишей.
- **Приватность.** Голос распознаётся на компе. Наружу уходит только то, что ты включил (Telegram, облачная озвучка).
- **Диагностика.** Логи в `~/.vibevim/logs/`. `vv doctor` проверяет зависимости и доступы macOS (микрофон, уведомления, Accessibility).

## Не делаем (в этой версии)

- Свой редактор кода. Для ручных правок есть `e` — открыть в твоём редакторе.
- Своего агента поверх API. Внутри всегда `claude`. Точку подключения других агентов (Codex, Gemini) оставим в коде, но не делаем.
- Windows и Linux. Устройство позволит добавить их потом.
- GUI-приложение. Окно тиктока — единственное исключение.
